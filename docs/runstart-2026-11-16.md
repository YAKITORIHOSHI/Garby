## 2 — The tab

Developer tests… → **RunStart**.

- **Steps.** One row per step: a dropdown (**Forward**, **Backward**, **Turn left**, **Turn
  right**, **Bump calibrate**) and the number of steps (1–100 000). **+ Add step** adds a row
  (up to 20) and the red bin deletes one. The list scrolls past about seven rows.
- **Max speed** (10–8000 steps/s, default 2000) and **Acceleration** (100–20 000 steps/s²,
  default 4800) are on the side. For comparison, the remote's Fast is 2000 and routes use up to
  5600 at 4800. The cap was 5600 in the first build and is 8000 since `RUNSTART-20261116B`
  (owner: "it should be max at 8000"), the speed the Nov 11 Calib floor test drove at.
- **Start run** asks for confirmation, then GARBY drives the steps in order. Each step starts
  and ends at rest, with 250 ms between steps:
  - Forward and Backward move both wheels.
  - Turns spin in place: for Turn left, the left wheel goes back and the right forward. This
    uses the current guess of which motor is the left wheel, as the remote does.
  - Bump calibrate goes forward in 100-step bumps with 300 ms pauses, like a route's first
    step.
- **No LiDAR, sonar or gyro checks.** As the owner asked, nothing watches for obstacles.
- **Locked.** While a list runs, and while it is stopped part-way, every row, the speed boxes,
  **+** and the bins are greyed out, so Continue and Reverse act on exactly what is shown.
  Each row is marked ✔ done or ▶ 420/980 (■ when stopped).

## 3 — Stopping, Continue run, Reverse to start

- **What stops it:**
  - **EMERGENCY STOP**: on this window, the main window or the phone.
  - **The lease**: the Pi renews the list every 200 ms. If that stops for 0.8 s, the robot
    stops. That happens when the Developer window is closed, the ssh session drops, the
    monitor stops or the link is lost.
  - **A link or protocol STOP, or a reset.**
- **GARBY remembers exactly where it stopped.** Every step's wheel targets are fixed when the
  list starts, from the wheel positions at that moment, so the step counters give the exact
  place.
  - **Continue run** finishes the list from there.
  - **Reverse to start** drives it back to where it began. It undoes the current step first,
    then each earlier step in reverse order: the same wheel steps the other way, with bumps
    undone in one move.
  - If the emergency stop is on, either button releases it first (after you confirm), the
    same confirmed release as the main window. The list then moves.
- **After it finishes**, the rows unlock for editing and **Reverse to start** still takes the
  last list back.
- **What forgets the saved list:**
  - **Discard saved** (this also unlocks the rows);
  - starting a new list;
  - any other motion: a bench test, the remote, Manual disposal or any route;
  - a restart of the motor controller.
- The main window's Continue run / Reverse to start stay for routes. After a RunStart stop it
  shows Release stop only; the list's own buttons are in the RunStart tab. If the monitor
  restarts while a list is stopped part-way, the tab shows that list again from the robot's
  report.
- A test ended by the emergency stop now reports it as the emergency stop. Before, the
  bridge's relayed stop made it read "the link to the robot dropped".

## 4 — Wire format

All three parts carry it, as build `RUNSTART-20261116B` (`RUNSTART-20261116` capped speed at
5600):

- `[TEST:<id>:P:<speed>:<accel>:<op><steps>,...]` starts a list.
- `[TEST:<id>:C:<saved>]` continues the saved list; `[TEST:<id>:U:<saved>]` reverses it.
- `[TEST KEEP:<id>]` renews the lease.
- `[RUN CLEAR:<saved>]` discards the saved list.
- The robot answers with `[RUN AT:<id>:<step>:<done>]` and
  `[RUN SAVED:<id>:<step>:<done>:<speed>:<accel>:<program>]` (or `[RUN SAVED:0]`).

The longest list (20 steps of 100 000) is 196 characters and fits one Bluetooth frame. Full
description: `SYSTEM_ARCHITECTURE.md`, "Finite developer tests".

## 5 — Limits

- **Open loop.** Step counters are commanded pulses. A stalled or slipping wheel is not
  detected, and Continue/Reverse trust the counters.
- **Instant stop.** The emergency stop is immediate; at speed a wheel can overrun a little
  without the counter seeing it.
- **Turn steps are not degrees.** The old open-loop calibration was 4900 steps for 90°, so
  980 steps is about 18°. That figure is not measured.
- **Nothing watches for obstacles** during a list.

## 6 — Upload and first check

**MCU upload requirement: Both.** Upload the complete `BLE_Receiver-Final` and
`MAIN_EXECUTOR_CODE` sketches, and deploy the whole `RasPi/` folder; all are
`RUNSTART-20261116B`. The owner flashed `RUNSTART-20261116` on both boards at 11:22 and 11:25
EST, and lists ran on the robot (11:40 at 2000 steps/s, 11:41 at 5600). On those boards a list
above 5600 steps/s is never confirmed, and the tab says which firmware it needs.

Wheels lifted first:

1. RunStart: Forward 2000, Turn left 980, Backward 2000, at 2000 / 4800. **Start run**: both
   wheels forward, then opposite ways, then back, and the rows lock.
2. Start it again and press EMERGENCY STOP half-way, then **Continue run**: it finishes.
3. Again, then **Reverse to start**: it drives back to where it began.
4. Close the Developer window mid-run: it stops within a second. Reopen it, and Continue
   run finishes the list.
5. On the floor, start with a short, slow list and a clear area.
